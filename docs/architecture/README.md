# Архитектура Business Metrics Analyzer

Документация архитектуры приложения для практической работы № 4.
Архитектура Business Metrics Analyzer
1. Обзор системы
Business Metrics Analyzer — веб-приложение для импорта данных о продажах, расчёта KPI (выручка, средний чек, конверсия, рентабельность), отображения дашбордов и экспорта отчётов Excel/PDF. Роли: коммерческий директор, менеджер по продажам, аналитик, администратор. Внешние зависимости: источник данных 1С/CSV/Excel и SMTP.

3. Выбранный архитектурный стиль
Слоистый монолит с элементами Clean Architecture: единое развёртываемое приложение, чёткие границы между Presentation, Application, Domain и Infrastructure. Решение уменьшает операционную сложность MVP и позволяет позднее выделять сервисы. Подробнее: [ADR-001](adr/ADR-001.md).
4. Диаграммы
- Контекст C4 L1 — подготовка/перенос файла из части Марины.
- Контейнеры C4 L2 — подготовка/перенос файла из части Марины.
- Компоненты UML — подготовка/перенос файла из части Даши.
- Развёртывание UML — редактируемая диаграмма Лизы.

Repository, Unit of Work, Service Layer, Factory, Strategy, DTO, Adapter и Observer. Подробное обоснование и примеры кода находятся в [patterns.md](patterns.md) (материал части Даши).
7. Технологический стек
Python 3.10+, FastAPI, Uvicorn, SQLAlchemy, PostgreSQL 16, Redis 7, Docker, Nginx, pandas, openpyxl, MinIO/S3, SMTP, JWT. PDF-экспорт предусматривает отдельный генератор отчётов.

Ресурсы являются проектными оценками из задания, не результатами нагрузочного тестирования. Клиентский браузер взаимодействует с Nginx по HTTPS; Nginx направляет запросы в FastAPI; приложение работает с PostgreSQL и Redis; сервис отчётов использует S3 API и SMTP.
8. Ограничения и компромиссы
Монолит проще для MVP, но его компоненты масштабируются совместно. Redis добавляет инфраструктурную зависимость; при недоступности кэша расчёт KPI должен выполняться по данным БД. JWT требует контроля срока действия токенов и безопасного хранения секретов. Пакетный импорт требует валидации и контроля повторных загрузок. Наличие компонентов на схеме не означает, что они уже развернуты.
9. План развития архитектуры
Провести нагрузочное тестирование на объёме до 1 млн записей; внедрить фоновые задачи импорта; настроить мониторинг и резервное копирование; при необходимости выделить сервис отчётов в самостоятельный процесс и масштабировать его отдельно.
