# Архитектура Business Metrics Analyzer

Документация архитектуры приложения для практической работы № 4.
Архитектура Business Metrics Analyzer
1. Обзор системы
Business Metrics Analyzer — веб-приложение для импорта данных о продажах, расчёта KPI (выручка, средний чек, конверсия, рентабельность), отображения дашбордов и экспорта отчётов Excel/PDF. Роли: коммерческий директор, менеджер по продажам, аналитик, администратор. Внешние зависимости: источник данных 1С/CSV/Excel и SMTP.

3. Выбранный архитектурный стиль
Слоистый монолит с элементами Clean Architecture: единое развёртываемое приложение, чёткие границы между Presentation, Application, Domain и Infrastructure. Решение уменьшает операционную сложность MVP и позволяет позднее выделять сервисы. Подробнее: [ADR-001](adr/ADR-001.md).

Ресурсы являются проектными оценками из задания, не результатами нагрузочного тестирования. Клиентский браузер взаимодействует с Nginx по HTTPS; Nginx направляет запросы в FastAPI; приложение работает с PostgreSQL и Redis; сервис отчётов использует S3 API и SMTP.
8. Ограничения и компромиссы
Монолит проще для MVP, но его компоненты масштабируются совместно. Redis добавляет инфраструктурную зависимость; при недоступности кэша расчёт KPI должен выполняться по данным БД. JWT требует контроля срока действия токенов и безопасного хранения секретов. Пакетный импорт требует валидации и контроля повторных загрузок. Наличие компонентов на схеме не означает, что они уже развернуты.
9. План развития архитектуры
Провести нагрузочное тестирование на объёме до 1 млн записей; внедрить фоновые задачи импорта; настроить мониторинг и резервное копирование; при необходимости выделить сервис отчётов в самостоятельный процесс и масштабировать его отдельно.

### Диаграмма развёртывания приложения

Диаграмма развёртывания отражает физическую архитектуру веб-приложения Business Metrics Analyzer, предназначенного для загрузки данных о продажах, расчёта ключевых показателей эффективности (KPI), визуализации результатов и формирования отчётов.

Приложение развёртывается в облачной инфраструктуре с использованием контейнеризации Docker.

**Основные узлы архитектуры:**

1. **Клиентское устройство** — пользователь взаимодействует с приложением через веб-браузер. Передача запросов осуществляется по защищённому протоколу HTTPS.
2. **Веб-сервер Nginx** — принимает входящие запросы, обеспечивает TLS-шифрование и перенаправляет запросы на сервер приложения.
3. **Сервер приложения FastAPI/Uvicorn** — обрабатывает HTTP-запросы и обеспечивает взаимодействие между пользовательским интерфейсом и внутренними сервисами.
4. **Сервисы приложения** — реализуют импорт данных о продажах, расчёт KPI и формирование отчётов.
5. **PostgreSQL 16** — обеспечивает постоянное хранение данных о продажах, пользователях и рассчитанных показателях.
6. **Redis 7** — используется для кэширования результатов расчёта KPI и ускорения повторных запросов.
7. **MinIO/S3** — предназначен для хранения сформированных файлов отчётов.
8. **Внешние системы** — источники данных 1С, CSV и Excel, а также почтовый сервис SMTP для отправки уведомлений.

**Взаимодействие компонентов**

Пользователь отправляет запрос через браузер на веб-сервер Nginx. Запрос передаётся серверу FastAPI/Uvicorn, который вызывает необходимые сервисы приложения. Для хранения и получения данных используется PostgreSQL, для ускорения обработки запросов — Redis, а для сохранения отчётов — MinIO/S3.

Импорт данных осуществляется из внешних источников, а отправка уведомлений — через SMTP.

**Вывод**

Разработанная архитектура обеспечивает разделение функциональных компонентов, централизованное хранение данных, кэширование результатов и возможность развёртывания приложения в контейнерной среде Docker. Выбранная структура соответствует требованиям учебного проекта и допускает дальнейшее масштабирование системы.
