# ADR-002. Выбор СУБД PostgreSQL

## Статус
Принято

## Контекст
Система хранит пользователей, продажи и рассчитанные KPI. Планируемый объём — до 1 млн записей о продажах; требуются транзакции при импорте и выборки по периодам.

## Решение
Использовать PostgreSQL 16 как основную реляционную СУБД. Для доступа к данным предусмотреть SQLAlchemy и Repository; целостность пакетного импорта обеспечить транзакциями Unit of Work. Индексы и производительность запросов проверить на тестовых данных.

## Альтернативы
1. SQLite — минимальные требования к инфраструктуре, но менее удобна для многопользовательского серверного приложения и конкурентной записи.
2. MySQL — полноценная реляционная СУБД, но не даёт существенного преимущества для требований данного учебного проекта.

## Последствия
- Плюсы: транзакции, ограничения целостности, развитые средства запросов и индексирования.
- Минусы: отдельный контейнер БД, настройка резервного копирования и администрирования.
