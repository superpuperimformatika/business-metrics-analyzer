# ADR-003. Выбор JWT для аутентификации

## Статус
Принято

## Контекст
Система имеет четыре роли: коммерческий директор, менеджер по продажам, аналитик и администратор. Необходимо разграничивать доступ к операциям API; по условиям задания применяется JWT.

## Решение
Использовать JWT для аутентификации запросов REST API. Проверять подпись, срок действия и необходимые claims токена; роли и права доступа проверять на стороне сервера. Секреты и ключи хранить вне исходного кода; использовать HTTPS. Для изменения прав пользователя предусмотреть проверку актуальных разрешений либо механизм отзыва токенов.

## Альтернативы
1. Серверные сессии — проще централизованный отзыв, но требуют хранилища сессий и дополнительной настройки при масштабировании.
2. API-ключи — подходят для машинных интеграций, но неудобны для интерактивной авторизации пользователей и ролей.

## Последствия
- Плюсы: удобная авторизация запросов API и независимость от серверной сессии при проверке корректно подписанного токена.
- Минусы: требуется контролировать срок жизни, отзыв токенов, хранение ключей и защиту от компрометации.
